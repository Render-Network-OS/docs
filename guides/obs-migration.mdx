Moving a stream setup means deciding where production, controls, overlays, and output will run. Use this guide to compare your existing OBS workflow with the 555stream options available to you.

## Decide What Needs to Change

List the sources, scenes, audio routing, guests, recordings, overlays, plugins, and destinations your stream depends on.

Identify the part you want to change and the reason: a different control workflow, a shared production task, or an integration with an interactive experience. Retain the working setup while evaluating the alternative.

## Compare the Responsibilities

| Part of the workflow | What to check before changing it |
| --- | --- |
| Scenes and sources | Layouts, capture devices, media files, transitions, and source dimensions |
| Audio and guests | Routing, monitoring, guest connections, and synchronisation |
| Plugins and modules | Which functions are needed and whether the chosen setup supports an equivalent |
| Overlays | How the overlay is provided, configured, and updated |
| Output | Supported destination, ingest method, resolution, frame rate, and bitrate |
| Operator access | Who can control the stream and how permissions are granted |
| Recording and recovery | How work is retained and how the existing setup can be restored |

Compare the features offered by each setup, including its supported plugins, access controls, and observed performance.

## Move One Part at a Time

1. Save the existing scenes, settings, and a list of the required assets.
2. Prepare the corresponding layout and controls in the setup you are evaluating.
3. Confirm the input, output, and access requirements from that setup’s documentation.
4. Run a private test or local recording, checking the complete visual and audio result.
5. Compare the result with the original and record any missing features.
6. Change the public workflow only when the intended setup is ready, keeping a way back to the previous configuration.

OBS’s [Quick Start Guide](https://obsproject.com/kb/quick-start-guide) covers its configuration wizard, sources, audio, and a test before streaming.

## Keep a Combined Setup Where Useful

An OBS Browser Source can include a web-based overlay in an OBS scene. Use an overlay URL supplied for that purpose by the product you are integrating; a studio control page and an overlay output are different things.

[OBS Integration](/guides/obs-integration) explains this connection. You can retain OBS for production while evaluating a compatible overlay.

## Check Performance

Compare the observed output, connection stability, audio timing, and dropped frames during a representative test. Use the destination’s supported settings rather than assuming one resolution or bitrate fits every stream.

Check one destination first, then the intended combined setup. Capacity depends on where the encoding and distribution work is performed.
