### sw4p: Cross-Chain Settlement

sw4p provides native USDC settlement across Ethereum, Base, Arbitrum, Polygon, Optimism, Avalanche, and Solana, plus USDT corridor support including Tron. Testnet and devnet flows are live; mainnet is paused during the current protocol upgrade window and returns with the upgrade.

The mechanism is straightforward: burn at the source chain, attest, mint at the destination chain, native funds at both endpoints, no wrapped tokens, no liquidity-pool slippage. End-user flows are non-custodial; users sign from their own wallet. The engine never holds user balances. **Universal gas abstraction**: users pay gas in the asset they're moving (USDC, USDT) on every supported chain, they never have to hold a chain's native token.

**Security posture:** Checkpointed 15-state settlement lifecycle with explicit recovery actions, rate limiting, authentication, circuit breakers, fee audit logs, route-specific security policies, and continuous observability. The gas abstraction layer ships with 1,743+ adversarial tests.

**SDKs:** TypeScript (`@sw4p/sdk`) and Rust (`sw4p-sdk`). Agent surface: `@sw4p/kit` (pre-publish). Full documentation at [docs.sw4p.io](https://docs.sw4p.io).

sw4p serves as the cross-chain backbone for AGG payment routing and Hyperlink resolution, any payment originating from a supported chain settles natively on the destination chain through the engine.

## II. The Protocol Suite: 555x402

The 555x402 protocol suite implements the HTTP 402 Payment Required standard for verifiable attention, aggregated payments, and smart payment links. Three components work together to create a complete attention-to-payment pipeline.

### VAP: Verifiable Attention Protocol

**v1 (Live):**
VAP v1 provides cryptographic proof that a participant was actively engaged. A bidirectional handshake establishes a WebSocket session. Heartbeat pulses at dynamic intervals (based on trust score) carry Ed25519 signatures with replay protection via nonces. A three-layer anti-fraud engine combines behavioral heuristics (entropy analysis, timing analysis, reputation scoring), active challenges ("Click the Glitch" overlays, input sequences), and economic penalties (slashing, cooldowns).

Every arcade score, every stream view, and every ad impression passes through VAP. If VAP cannot verify the attention, the event does not enter the economic pipeline. There are no exceptions.

**v2 (Validated, 234 Tests Passing):**
VAP v2 introduces epoch-based verification with 6-hour epochs (four per day), Attention Credits (1 AC = $0.001 USDC), a burn loop ($555 burned at oracle price → equivalent ACs minted → advertisers bid ACs), and stake-weighted participation with a logarithmic formula capped at 5.0x.

The ContributionProof format is 296 bytes: session reference, epoch identifier, stake reference, and cryptographic signature. The system is entity-agnostic, no protocol-level distinction between human and AI participants.

**Security validation results (v2):**
All five attack vectors return negative ROI for attackers. Sybil attacks achieve -81.7% ROI with a maximum 1.80x multiplier even at 100 identities. Fabrication returns -179.7% ROI. Collusion, eclipse, and griefing attacks all produce negative returns for the attacker. 234 tests pass across the full validation suite. All five attack trees are marked SECURE.

VAP v2 deployment is scheduled for Phase 2 of the roadmap, dependent on the completion of cNFT Audience Inventory and lock verification infrastructure.

### AGG: Payment Aggregator

**Status: Partially Implemented**

AGG is a DEX-aggregator-pattern payment router: n tokens on m chains settle as 1 token on 1 chain (USDC on Solana). The HTTP 402 handshake negotiates payment terms. Pathfinding considers gas cost, swap slippage, and bridge time to calculate optimal routes.

Solana settlement uses Versioned Transactions (v0) and Address Lookup Tables (LUTs) to pack complex logic, SPL swap routing, fee extraction, payment transfer, and memo, into a single atomic transaction with sub-2-second finality.

**Live:** Solana-native settlement with best-execution SPL routing.
**In development:** Cross-chain settlement and universal gas abstraction ship through [sw4p](/sw4p).
**Platform fee:** 0.5–1.0% deducted from settlement amount.

### Hyperlink: Smart Payment Links

**Status: Partially Implemented**

Live at [555hyper.link](https://555hyper.link). Hyperlinks are smart URLs that resolve to blockchain transactions:

`https://555hyper.link/p/{code}?ref={referrerId}`

The resolution flow: user clicks → browser detects wallet → gateway returns metadata (OG tags + deep link) → wallet resolves transaction payload → user signs → blockchain confirms.

**Use cases already in production:**

## III. The Economic Engine

### The Canonical Revenue Cascade

Every dollar that enters the RNDRNTWRK follows the same deterministic path. The cascade is identical at both levels of the ecosystem, platform level ($555) and creator economy level (individual creator tokens).

**Step 1, ARP (10%):**
Ten percent of gross revenue is taken off the top and distributed to verified audience members via VAP attention proofs. This is policy-enforced and non-optional. The Audience Reward Pool is the mechanism by which viewers earn real value for real engagement.

**Step 2, Creator/Platform Split (90% remaining):**
The post-ARP revenue splits between Creator and Platform. At the platform level, this is a fixed 50/50 split. At the creator economy level, the split is configurable within governance bounds (20/80 to 80/20).

**Step 3, Platform Allocation (from Platform's share):**
- 70% → Treasury (operations, development, growth)
- 20% → $555 buyback-and-burn (minimum, configurable above)
- 5% → $555 token reserve
- 5% → SOL/USDC reserve

The 20% minimum buyback-and-burn creates structural deflation. Every dollar of platform revenue permanently reduces $555 circulating supply. This is not a promotional burn event, it is an automated, ongoing mechanism embedded in the settlement pipeline. Buybacks execute weekly, aligned with the Monday settlement cycle, using programmatic DEX routing on Solana.

## V. Governance

### Framework (Designed, Not Yet Live)

Stake-weighted voting governs four protocol objects: SplitConfig (creator/stakeholder split bounds), BuybackPolicy (minimum buyback percentage), UnbondingPolicy (staking exit cooldowns), and VenuePolicy (DEX allow-lists and oracle sources).

**Lifecycle:** Proposal creation → Voting window (stake-weighted, on-chain records) → Execution delay (timelock) → Activation (contract state updated, public receipts).

**Default bounds:** Split range 20/80 to 80/20 (creator/stakeholders). Minimum buyback ≥20%. Unbonding periods defined per creator within published limits.

### VAP v2 Three-Layer Governance

When deployed, VAP v2 introduces a three-layer governance architecture: ve$555 DAO (token-weighted governance for protocol-level parameters), Algorithmic Layer (automated adjustment within DAO bounds), and Alice Layer (real-time operational decisions within algorithmic bounds).
