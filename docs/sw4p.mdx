# sw4p

**sw4p is the settlement engine of RNDRNTWRK.** It collapses fragmented cross-chain value movement into a single settlement layer for routing, gas abstraction, and execution. Bridges are not exposed to the caller; sw4p resolves the route, coordinates settlement, and tracks the transaction through completion.

Cross-chain value fragments across rails, fee models, and chain-specific logic. That makes settlement operationally heavy, expensive to integrate, and hard to standardize across products. sw4p is the single settlement primitive: cross-chain movement becomes operational, not exceptional.

## How It Works

sw4p starts from the outcome, not the bridge choice.

1. A client expresses the settlement intent.
2. sw4p resolves the route for the token and corridor.
3. The engine provisions gas where needed and coordinates execution.
4. Settlement tracks through a persistent 15-state lifecycle until completion.
5. Recovery logic handles retries, stalled transfers, and partial failures.

For native USDC corridors, the current production flow is:

**Burn → Attest → Mint**

No wrapped tokens. No liquidity pool dependency. No manual bridge selection for the end user. The USDC on the destination chain is native.

## Routing and Settlement

Callers express the outcome they want: "send X USDC from chain A to recipient on chain B." The engine resolves the route, provisions gas, executes the move, and tracks the transaction through completion. Underlying rails are an implementation detail of the engine, not a choice exposed to the caller.

The engine is built around ERC-7683-compatible intents. Competitive solver-based execution is a first-class expansion path, not a retrofit.

## Beyond Transfer

Transfer is the floor. The same engine resolves recurring flows, intent execution, and agent-mediated value movement:

- **DCA (dollar-cost averaging):** recurring buys with best-execution SPL routing on Solana.
- **Limit orders:** price-triggered fills monitored by a persistent background worker.
- **Agent API:** batch settlement, cross-chain portfolio aggregation, rebalance planning and execution.
- **Solver auction framework:** ERC-7683-compatible intents with competitive filler execution.
- **Universal storefront:** multi-tenant settlement surface, per-project config, custom subdomains.
- **Fiat on-ramp:** Transak integration with webhook-settled completion.
- **Referrals:** codes with automatic fee splitting at settlement time.
- **Telegram and Discord bots:** conversational settlement, same engine.

## Security

sw4p is hardened as a settlement system, not as a frontend.

The stack ships rate limiting, authentication, circuit breakers, fee audit logs, per-route security policies, and observability across the full settlement lifecycle. The gas abstraction layer carries 1,743+ adversarial tests. Settlement state is checkpointed, with explicit recovery actions for every stalled transition.

End-user flows are non-custodial: users sign from their own wallet. The engine never holds user balances; settlement is native at both endpoints. Internal signing material used for protocol-side execution is managed by sw4p infrastructure and is not exposed to integrators.

<Note>
  **Supported production asset:** USDC. The $555 token is a Solana SPL token and is not bridged by sw4p. Any USDC-to-555 conversion is explicit product policy, not an implied default.
</Note>

## Integration Inside RNDRNTWRK

sw4p is the settlement backend for cross-chain routing and value movement across the network.

- **AGG** routes cross-chain payments through sw4p.
- **Hyperlink** resolves cross-chain payment links through sw4p.
- Asset and route expansion follows the sw4p routing roadmap, not per-product one-offs.

## Interfaces

One engine, many surfaces.

### SDK

**TypeScript:** `@sw4p/sdk`. 30+ methods covering transfer, estimate, status, portfolio, rebalance, DCA, limit orders, intents, ERC-7683, x402 helpers, and the Solana two-step flow.

**Rust:** `@sw4p/rs-sdk`. Settlement primitives, native to server-side and agent runtimes.

### Widget

**React / iframe:** `@sw4p/widget`. Embeddable settlement surface, drop-in.

### Bots

Telegram and Discord: conversational settlement on the same engine, not a separate surface.

### Storefronts

Multi-tenant settlement frontends with per-project configuration, custom subdomains, and token picker.
