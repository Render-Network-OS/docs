# The Routing Layer

<Info>
**Status:** Partially implemented. Solana-native settlement is live. Cross-chain settlement and built-in gasless ship through [sw4p](/sw4p).
</Info>

**AGG (Aggregator)** is the routing layer for value movement across the RNDRNTWRK. It abstracts away the complexity of blockchain payments, allowing users to pay with any token on any chain.

## Routing Architecture

AGG functions like a payments aggregator. It solves the "n-to-1" problem: Users have `n` tokens on `m` chains, but the Merchant wants `1` specific token on `1` chain.

### 1. The 402 Handshake
The protocol begins when a client hits a gated resource.

**Server Response (402 Payment Required)**
```http
HTTP/1.1 402 Payment Required
WWW-Authenticate: 555x402 realm="sector-13",
  amount="5.00",
  token="USDC",
  chain="solana",
  recipient="HuW...9zP"
```

### 2. Pathfinding
The AGG Client (SDK) calculates the optimal route based on the user's wallet state.

**Factors:**
- **Gas Cost**: Solana (less than $0.001) vs Base vs Polygon.
- **Swap Slippage**: If paying with SOL to settle in USDC (best-execution SPL routing on Solana).
- **Bridge Time**: If paying from Base to settle on Solana (through [sw4p](/sw4p)).

**Example Route:**
`User (Base/ETH) -> swap to USDC -> sw4p settlement -> Solana (USDC) -> Merchant`

### 3. Solana Settlement (v0 + LUTs)
On Solana, AGG uses **Versioned Transactions (v0)** and **Address Lookup Tables (LUTs)** to pack complex logic into a single atomic transaction with sub-2-second finality.

**Transaction Structure:**
1. **Swap Instruction**: Best-execution SPL routing to convert User Token -> USDC.
2. **Fee Instruction**: Transfer platform fee to Treasury.
3. **Payment Instruction**: Transfer remaining amount to Merchant.
4. **Memo Instruction**: Attach `orderId` for reconciliation.

```rust
pub fn settle_payment(ctx: Context<Settle>, amount: u64) -> Result<()> {
    token::transfer(ctx.accounts.user, ctx.accounts.merchant, amount)?;
    emit!(PaymentSettled { id: ctx.accounts.order.id });
}
```

## Fee Structure

AGG enforces a transparent fee model:

| Fee Type | Rate | Payer | Description |
| :--- | :--- | :--- | :--- |
| **Platform Fee** | 0.5–1.0% | Merchant | Deducted from the settlement amount. |
| **Gas Fee** | Variable | User | Network costs (built-in gasless on Solana). |

## Cross-Chain Settlement

For cross-chain payments (e.g., Base → Solana), AGG hands the settlement intent to [sw4p](/sw4p). Native USDC settles on the destination chain — no wrapped tokens — and the merchant receives funds in their preferred chain and asset. The mechanics of routing, attestation, and recovery are an internal concern of the engine; integrators see one settlement primitive.

### Integrations
- **[sw4p](/sw4p)** — native USDC settlement across supported chains, USDT corridor including Tron, built-in gasless on Solana.
- **Best-execution SPL routing** — optimal SPL swap routing on Solana for any-token-in / USDC-out flows.
