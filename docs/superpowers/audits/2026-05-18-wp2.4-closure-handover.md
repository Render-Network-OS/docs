These are real traps the prior session hit. The receiving team should know about them so they do not re-discover them painfully.

1. **`ts-node@10.9` is broken on Node 22.** It silently throws an empty `{}` object because its ESM resolver uses a deprecated `fs.Stats` constructor. Use `npx --yes tsx` for any new TS deploy script invocation.
2. **Circle SCP `description` field rejects non-alphanumeric.** No parens, no plus signs, no slashes. Alphanumeric + spaces only.
3. **Circle entity-secret ciphertext is single-use per Circle call.** Reusing it across multiple chains in one wave returns code `177602`. Always regenerate inside the per-chain loop.
4. **Idempotency keys must be UUIDs per chain, per attempt.** Reusing a key across attempts is a silent collision. Use `crypto.randomUUID()`.
5. **`cargo test chain_registry` (without `--lib`) runs zero tests.** Bare pattern is interpreted as a binary spec. Use `cargo test --lib chain_registry`.
6. **Local `ulimit` will fork-bomb if you run all 7 chains' `cast call` probes in one shell loop.** Split into two scripts (ETH alone, then six remaining sequentially with `sleep` between groups) if you hit "Resource temporarily unavailable".
7. **Deploy script writes `deployed_addresses_v41.json` only for the chains it deploys in a given run.** If you run Round 2 covering 6 chains, ETH gets dropped from the file. Manual add was required after the wave; the closure docs reflect this.
8. **The 555 mono / sw4p-earn local checkout in this worktree is a stub** (`app/`, `services/` only, no `docs/`). If a step asks for sw4p-earn work, check `/Volumes/OWC Envoy Pro FX/desktop_dump/new/Work/555/sw4p-earn/` is actually populated before assuming you can branch there.
9. **`mainnet.json` is `include_str!`d into the Rust backend.** Any registry chain code that `chain_registry.rs::normalize_chain_code` does not know triggers a startup panic. Always pair a runtime registry chain addition with the `normalize_chain_code` arm and the test count bump.

## Glossary (one-line each)

- **WP2.4**: the work package that closed the V4.1 mainnet wave (deploy + evidence + hardening; no cutover).

- **Cutover gate**: per-chain explicit authorization to flip a chain's V4.0 to V4.1 across registry, services, indexer, and frontend. Always per chain, always explicit, never bundled with deploy.
- **Runtime registry**: `sw4p-backend/contracts/registry/mainnet.json`, embedded into Rust backend.
- **Deploy-target delta**: `sw4p-backend/contracts/scripts/deploy_targets_mainnet.json`, script-owned, holds chains we deployed but did not yet cut over.
