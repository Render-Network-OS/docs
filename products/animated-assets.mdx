<Info>**Planned library.** Animated Assets describes a reusable collection of motion elements for RNDRNTWRK media experiences.</Info>

## What the Library Is For

Motion can introduce a segment, highlight an event, explain a game result, or give a stream a recognisable visual style.

The library concept brings together reusable assets and the settings that shape them: colours, fonts, timing, placement, sound, and the events that trigger them.

## Asset Types

- **Overlays:** lower-thirds, sidebars, banners, carousels, and full-screen placements.
- **Reactions:** emotes, particle trails, confetti, chat highlights, and other short effects.
- **Game elements:** countdowns, result reveals, scoreboards, and win or loss animations.
- **Sponsor material:** branded introductions, endings, and transitions for a segment.
- **Clip frames:** animated borders and short transitions for recorded highlights.

Choose effects that support the information on screen and leave the stream readable.

## Packs and Creation

The planned library includes curated packs from creators and artists, along with tools for adapting or generating a pack around a theme.

A pack would group assets with shared colours, fonts, sound, and timing. Its description would explain the included files, adjustable settings, supported formats, and usage terms.

Theme-based recommendations and generation are part of the proposed creation model.

## Events and Triggers

An animation can be planned around a particular moment:

- A follow, subscription, tip, or community milestone.
- A game result, quest completion, or score change.
- The start or end of a sponsor segment.
- A chat keyword, moderator action, or scheduled announcement.

For each effect, identify the event it responds to, who may trigger it, how long it runs, and whether it can interrupt or overlap another effect. Check which events and controls the connected experience supports.

## Formats and Playback

The delivery design considers browser-rendered motion using WebGL or Canvas, Lottie animation files, sprite sheets, and video alternatives.

Choose a format supported by the intended overlay or player. Check file size, dimensions, transparency, fonts, and sound, then test the asset alongside the rest of the stream.

Prepare landscape, portrait, or mobile layouts for the audience's viewing format. A 1920×1080 composition is one landscape option; size and placement should follow the actual output.

Preloading, caching, and simpler fallback assets are ways to plan for consistent playback. Test motion and readability on the intended devices before using the asset in a programme.

## Licensing and Updates

Read the asset's usage terms for stream use, commercial work, modifications, redistribution, and attribution. Keep the source and version of each asset with the programme's production material.

A future pack listing would identify its creator, licence, price where applicable, and update history. Any artist payment or revenue-sharing arrangement would be defined by that offering.

When replacing an asset, retain the previous version so the production can return to it if needed.

## Preparing an Asset

1. Choose the asset and the moment it should support.
2. Confirm its usage terms and compatibility with the intended output.
3. Adjust colours, fonts, timing, sound, and placement.
4. Preview the full scene and test any connected event or operator control.
5. Apply it to the programme's layout or schedule, then check the actual output.

Use the tools offered by the chosen stream setup. [CTRL Panel](/products/ctrl-control-panel) explains the control-panel design, while [555stream](/555stream) covers stream preparation.
